The part that is hard to copy

Every alert has been watched failing

An alert rule that cannot fire looks exactly like one that has nothing to report. Reading it does not tell you which you have. So these rules are broken on purpose, and the test has to notice. Three real examples, all found that way, all fixed — and the three checks that find them in your own config:

An alert that read a label AWS never leaves empty

CloudWatch publishes unhealthy-host counts once per availability zone and once as a zone-less rollup. The rule matched both, so one unhealthy target paged three times. Its test passed because the fixture held a single series with no zone label at all — a shape AWS does not emit.

An alert that could not fire on a fresh install

The blackbox-exporter alarm read the probe job, which has one series per configured service. The shipped default configures none, so on a new install there was no series to read and the rule evaluated to nothing. Running the corrected test against the old rule says it plainly: 

FAILED: alertname: BlackboxExporterDown, time: 6m,  got:[]

A critical alert that went blind when its feeder died

The backup dead man's switch reads a metric pushed through a gateway. If the gateway itself died, the switch could not fire — the one failure mode it existed to catch. It now has its own alert behind it.

What this does not claim

It does not mean nothing will ever slip through. It means the rules were checked against what the real exporters emit rather than against a fixture someone wrote from memory, and that where a metric genuinely cannot be collected, the runbook says so in its first paragraph instead of implying coverage that is not there. A documented blind spot is worth more than a silent one.

Add-on

AI triage notes (Pro)

When a critical alert fires, the agent already in this kit gathers the firing rule's numbers, a 30-minute trend, the last error log lines, and any deploy from the last 2 hours, then asks Claude, with your own Anthropic API key, straight from your host to Anthropic, and posts a short triage note back to your Slack, Discord, Telegram, or email: probable cause with the numbers or log lines it rests on, whether a deploy lines up, what to check first, and what it did not see. Free runs the agent in dry run only, so you see exactly what it would send before anything leaves your network. Context is redacted at the agent (tokens, passwords, emails, webhook URLs) before it goes anywhere.

Not supported in year one: Alertmanagers outside the kit, self-hosting, chat back-and-forth with the note, automatic actions.
